## 2. 전처리 순서 및 근거

| 순서 | 단계 | 이유 |
|------|------|------|
| 1 | 컬럼 제거 | 분석 불필요 컬럼을 먼저 제거하여 이후 처리 대상 축소. EDA 상관분석에서 확인된 다중공선성 컬럼 정리 |
| 2 | 이상치 처리 | 이 데이터는 결측값이 0건이므로 결측 대체 순서 고려 불필요. 이상치 도메인 판단을 먼저 수행 |
| 3 | 타입 변환 | 계약일자를 datetime으로 변환하여 시계열 분석 준비 |
| 4 | 중복 제거 | 모든 처리 완료 후 최종 중복 검사. 컬럼 제거 후에도 중복 기준은 남은 전체 컬럼 일치 |

> 결측값 처리 단계는 **생략** — 원본 데이터에 결측값이 0건이므로 해당 없음.

## 3. 처리 내역

### 컬럼 제거
| 컬럼명 | 제거 사유 | 근거 데이터 |
|--------|----------|------------|
| 시도명 | 단일값 (서울특별시 100%) → 분석 가치 없음 | EDA 범주형 분석: 유니크 1개 |
| 입주년도 | 경과년수와 r=-0.99 (수학적 파생관계: 경과년수 = 계약년도 - 입주년도) → 경과년수 유지 | EDA 상관분석 결과 |
| 주차대수 | 세대수와 r=0.95 (거의 동일 정보) → 세대수 유지 | EDA 상관분석 결과 |

**제거하지 않은 컬럼 (검토 대상이었으나 유지):**
| 컬럼명 | 유지 사유 |
|--------|----------|
| 단지명 | 고카디널리티(6,191개)이나 지역별·단지별 가격 분석에 필요. 모델링 시 인코딩 전략 별도 검토 |
| 지번 | 고카디널리티(5,131개)이나 위치 기반 분석 시 필요. 모델링 단계에서 제거 검토 |
| 계약년도/계약월/계약일 | 계약일자(datetime) 변환 후 중복될 수 있으나, 연도별·월별 그룹 분석에 직접 사용되므로 유지. 모델링 시 제거 검토 |

**다중공선성 쌍에서 유지 컬럼 선택 근거:**
- **경과년수 vs 입주년도**: 경과년수 유지 — 거래금액과의 관계가 더 직관적(건물 노후도 지표). 입주년도는 절대 시점이므로 해석력이 낮음
- **세대수 vs 주차대수**: 세대수 유지 — 단지 규모의 대표 지표로 더 일반적. 주차대수는 세대수의 파생 정보

### 이상치 처리
| 변수 | 이상치 내용 | 건수 (비율) | 처리 방법 | 판단 근거 |
|------|-----------|------------|----------|----------|
| 층 | min=-3 (음수층) | 52건 (0.02%) | **유지** | 반지하/지하층은 부동산 도메인에서 실제 존재하는 층. -1층(40건), -2층(9건), -3층(3건)은 지하 거주공간으로, 제거 시 지하층 거래 정보 손실. 거래금액 분석에서 층수 효과를 정확히 반영하려면 포함이 적절 |
| 경과년수 | min=-2 (음수) | 29건 (0.01%) | 0으로 클리핑 | 입주 전 분양권 전매 거래. 경과년수 = 계약년도 - 입주년도이므로, 입주 전 거래 시 음수 발생은 논리적으로 정상. 그러나 "건물 노후도"라는 변수 의미상 음수는 해석 불가 → 0 처리. **행 삭제 대신 클리핑 선택** — 거래 자체는 유효하며 다른 변수(거래금액, 전용면적 등)는 정상 |

> **대안 검토**: 경과년수 음수 행을 삭제하는 방법도 가능했으나, 29건(0.01%)으로 극소수이고 다른 변수에는 이상 없어 정보 손실이 불필요하다고 판단. 클리핑이 더 보수적인 접근.

### 타입 변환
| 컬럼 | 변환 전 | 변환 후 | 사유 |
|------|---------|---------|------|
| 계약일자 | object (예: '2020-01-31') | datetime64[ns] | 시계열 분석, 날짜 연산, 기간 필터링에 필요. EDA에서 시계열 특성(2020~2024 추세)이 확인되어 datetime 변환 필수 |

### 중복 제거
| 중복 기준 | 중복 건수 | 비율 | 처리 |
|----------|----------|------|------|
| 전체 컬럼 일치 (14개 컬럼) | 5,746행 | 2.6% | 제거 (first 유지) |

> **중복 원인 추정**: 부동산 실거래 데이터는 국토교통부 API에서 수집되며, 동일 거래가 여러 차례 조회되거나 데이터 적재 과정에서 중복 발생 가능. 전체 컬럼이 완전히 일치하므로 동일 거래의 중복 신고로 판단.
